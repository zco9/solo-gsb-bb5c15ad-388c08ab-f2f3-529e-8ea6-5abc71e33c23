# 情景注入台（桌面事故演练）

主持人编排带**相对触发秒数**的注入卡片并启动演练；服务端维护可**暂停/继续**的虚拟时钟，
按 `(触发秒数, 序号)` 稳定揭示卡片，暂停期间时钟冻结、绝不推进。
支持 **2～8 个参与分组**：每组有独立**组加入码**，卡片可投递给「全员」或单个分组，
未命中的卡片在触发前后都不会离开服务端。
参与者凭 **6 位组加入码** 观看；断线重连时先恢复权威快照，再按递增事件 ID 接收增量，状态不回退。

技术栈：FastAPI + SQLite + 原生 HTML/JS（WebSocket 实时推送）。

## 启动（一条命令）

```bash
docker compose up --build
```

启动后访问：

- **Web 地址：** http://localhost:8000
- **端口：** `8000`（宿主机端口可在 `docker-compose.yml` 的 `ports` 中修改）

依赖安装与 SQLite 建表均已纳入启动流程，无需额外初始化步骤；数据持久化在命名卷 `inject-data` 中。

## 配置（环境变量，可在 docker-compose.yml 的 `environment` 中调整）

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `DATABASE_PATH` | `/data/inject.db` | SQLite 数据库文件路径 |
| `TICK_INTERVAL` | `0.25` | 服务端揭示扫描周期（秒） |

## 使用流程

1. **主持人**：打开首页 →「创建演练」。
   - 在「参与分组」中创建 **2～8 个参与组**（可随时重命名、删除），每组生成一个独立的
     **6 位组加入码**（点击即可复制）分享给对应参与者；已被卡片引用的分组不可删除，
     改名会实时同步到该组参与者页面。
   - 添加注入卡片（标题、触发秒数、内容），并选择目标「**全员**」或某个参与组。
   - 「开始演练」后，时钟运行中可「暂停 / 继续」；「重置」将时钟归零、收回全部已揭示卡片，
     **分组、组加入码与卡片目标均保留**。运行期间不可编辑卡片（需先暂停），保证揭示次序稳定。
   - 主持人始终看到**全部**卡片（含他组定向卡片），卡片上标注投递目标。
2. **参与者**：首页输入主持人分享的 6 位**组加入码** → 只看到投递给全员或本组、且已揭示的
   注入卡片与演练时钟。未触发、或投递给其他组的卡片在任何时刻都不可见（REST 与 WebSocket 均不返回）。

## 本地开发（不用 Docker）

```bash
pip install -r requirements.txt
DATABASE_PATH=./data/inject.db uvicorn app.main:app --reload --port 8000
```

## 同步与分组隔离协议

- 所有状态变更（卡片增删、揭示、时钟动作、分组增改删）都会落库为**全局单调递增事件**并广播。
- WebSocket 路径码为**房间码**时连接为主持人（看全部）；为**组加入码**时连接为对应参与者。
  服务端在锁内先按连接身份下发权威快照（含全局事件水位），再广播增量事件：
  - 定向事件（`group_id` 非空）只投递主持人与该组成员；
  - 分组管理事件只投递主持人（改名额外投递给被改名的那一组，用于同步组名）；
  - 对收不到内容的连接，服务端只发送同 ID 的 `watermark`（不含任何卡片内容），让该连接
    的水位与全局顺序保持单调一致。
- 客户端连接时携带 `last_event_id`，并丢弃 `id <= 水位` 的消息，因此刷新页面或
  断线重连后状态不回退，也不会混入他组内容。
- 服务重启时，处于运行中的房间会被安全冻结为「已暂停」，已流逝时间结算保留。
